# dsh-learn 项目目标（V1，已归档）

> V1 长期设计备忘：当前早期领先策略与 30 天执行顺序请以 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md) 和 [EXECUTION_CHECKLIST.md](EXECUTION_CHECKLIST.md) 为准。本文件保留完整课程产品的长期目标，不作为当前冲刺清单。

## 1. 项目愿景

DeepSeek Harness 的官方快速上手目前可以帮助用户启动 Web UI、配置模型和选择工作区，但从“第一次运行”到“理解权限、完成真实任务、判断是否成功”之间仍有明显空档。插件开发文档又很快进入 TypeScript、源码检出和 Cordis 配置，新用户容易在真正获得结果以前停下来。

`dsh-learn` 要补上这段距离：它给用户一个不会伤到真实项目的练习环境，一组逐步增加权限和复杂度的任务，以及能够判断结果是否正确的验证器。课程完成以后，用户不仅知道命令怎么复制，也知道 DSH 做了什么、改了哪里、什么时候需要批准，以及失败以后怎样恢复。

第二条路径面向插件初学者。它通过很小的可运行实验解释 Cordis 的两个核心问题：一个组件撤走以后，自己造成的影响能不能完整撤销；依赖出现、消失或换成另一个提供者时，相关组件能不能正确启停和重载。

## 2. 北极星目标

让一位没有使用过 DSH、但能够安装 Node.js 的用户，在 20 分钟内完成以下闭环：

1. 检查本机环境；
2. 启动官方 DSH；
3. 在生成的练习工作区执行一个只读任务；
4. 看懂工具调用和权限提示；
5. 用本地验证器确认结果；
6. 重置练习环境，不留下不可解释的改动。

北极星指标是 **TTFV（Time to First Verified Value，首次获得经过验证结果的时间）**，不是文章阅读量、视频播放量或 GitHub Star。

## 3. 目标用户

### Persona A：第一次使用 Agent 的普通用户

- 会安装桌面软件，命令行经验很少；
- 知道 DeepSeek 是模型，但不清楚模型、Agent 和 Harness 的区别；
- 最担心密钥泄漏、误改文件、费用和“运行了却不知道是否成功”；
- 目标是完成第一个安全任务，不需要理解插件框架。

### Persona B：会使用命令行的开发者

- 能运行 Node.js 项目，了解 Git 和基本 TypeScript；
- 想用 DSH 读代码、改文件、跑测试；
- 需要理解工作区、权限、日志、恢复和任务边界；
- 目标是建立可重复的日常使用方法。

### Persona C：插件初学者

- 会 TypeScript，但没用过 Cordis；
- 容易把插件理解成一次性执行的模块，不清楚 effect、依赖声明、fiber 和 HMR；
- 目标是写出能够正确加载、卸载、响应依赖变化并经过测试的最小插件。

### 暂不优先服务

- 完全无法安装 Node.js、也没有人协助的用户；
- 需要生产环境部署、多人权限治理或企业合规方案的团队；
- 希望通过课程学习论文完整形式化证明的研究者；
- 希望一键运行未经审查第三方插件的用户。

## 4. 产品目标

### G1：把第一次成功变成可验证结果

用户完成课程以后，验证器必须能根据工作区状态、产物和命令结果判断通过或失败，不能只让用户对照截图猜测。

初始目标：

- 10 位新用户内，至少 7 位无需实时人工救援完成核心课程；
- 核心路径 TTFV 中位数不超过 20 分钟；
- 失败信息必须指出下一步动作，不能只输出堆栈；
- 同一课程连续执行 `setup -> check -> reset -> setup`，结果保持一致。

### G2：建立安全、可恢复的练习边界

基础课程只允许写入 `dsh-learn` 生成的临时或用户明确指定的练习目录。重置操作必须可重复，且不能删除范围不明的路径。

初始目标：

- 基础课程不读取或改写练习目录外的用户文件；
- 不记录、上传或回显 API Key；
- 所有文件改动都能由课程清单解释；
- 本地可恢复动作提供自动 reset；
- 网络调用、费用、Git 推送、发布等不可自动回滚动作，在执行前明确显示边界。

### G3：让教程与版本变化一起维护

每课保存最后验证的 DSH 版本或 commit、Node 版本范围、系统和日期。课程不兼容时应显示 `stale/blocked`，而不是让用户在已知失效的步骤上反复尝试。

初始目标：

- 支持的每个 DSH 基线都跑一遍无 Key smoke test；
- 核心课程在发布前通过 macOS、Windows 和 Linux 测试矩阵；
- 上游发生破坏变化后，48 小时内更新兼容状态，修复时限可以另行评估；
- 所有版本条件集中在兼容数据文件，不散落硬编码在文章中。

### G4：把 Cordis 理论转成可观察实验

插件学习路径不要求用户先读完 88 页论文，而是通过实验看到两件事：

- 时间可组合性：组件注册工具、事件或资源以后，卸载时影响按正确顺序撤销；
- 空间可组合性：消费者声明依赖，提供者出现时激活，提供者撤走时消费者先停用，恢复提供者后重新激活。

初始目标：

- 每个核心概念至少有一个无需 API Key 的自动化实验；
- 实验同时覆盖成功路径、故意错误和恢复路径；
- effect 实验验证“没有残留注册、监听器和定时器”；
- dependency 实验验证组件状态变化和卸载顺序；
- 课程明确说明访问控制不等于沙箱。

### G5：把用户摩擦转成高质量上游反馈

课程失败报告应能脱敏导出环境、版本、课程 ID、步骤和错误，让维护者能够复现，而不是只收到“运行不了”。

初始目标：

- 一条命令生成脱敏诊断包；
- 报告默认不包含 API Key、完整主目录路径、文件正文和会话隐私；
- 每个确认的上游问题都有最小复现和验证条件；
- 重要反馈进入公开 GitHub Discussion，并链接回对应课程问题。

## 5. 非目标

MVP 不承担以下工作：

- 不重新实现 DeepSeek Harness；
- 不提供或转售模型 API；
- 不承诺所有第三方插件安全；
- 不把 Cordis 访问控制描述成恶意代码沙箱；
- 不对真实用户项目执行自动清理或恢复；
- 不制作完整插件市场；
- 不在首版提供云端账户、排行榜、社交功能或付费课程；
- 不为了覆盖所有系统而延迟最小可用版本，但公开发布前必须明确支持矩阵。

## 6. 成功指标

| 指标 | Alpha 目标 | Beta 目标 | 说明 |
|---|---:|---:|---|
| 核心路径完成率 | >=70% | >=80% | 不含主动退出和不满足前置条件的人 |
| TTFV 中位数 | <=20分钟 | <=15分钟 | 从运行 preflight 到第一个课程通过 |

| 插件实验自动通过率 | >=90% | >=95% | 在锁定的兼容基线上 |

### 产品质量

| 指标 | 目标 |

| 已知不兼容课程仍显示可运行 | 0 |
| 错误信息带可执行下一步 | 100% 核心错误 |

### 社区影响

| 指标 | 30天 | 90天 |
|---|---:|---:|
| 完成核心课程的独立用户 | 30 | 200 |
| 有效失败报告 | 10 | 50 |

## 7. 里程碑

### M0：规划与上游基线（建议 2026-08-15 前）

- 产品目标、课程结构、支持系统和安全边界有书面决定；
- 锁定一个 DSH commit/npm 版本作为开发基线；
- 把官方启动、工作区、权限和插件流程实际跑一遍；
- 完成风险登记和课程 manifest 草案。

退出条件：团队可以明确回答首版做什么、不做什么、怎样判断完成。

### M1：可运行纵向切片（建议 2026-08-20 前）

- `preflight`、`setup`、`check`、`reset` 四个命令可用；
- 一个完全无 API Key 的课程能够从头走通；
- 状态保存在练习目录内；
- reset 有路径保护和自动测试。

退出条件：在一台干净机器上，能用 README 独立完成一课并恢复现场。

### M2：私有 Alpha（建议 2026-08-27 前）

- 普通用户核心 6 课可用；
- 至少支持 macOS 和 Windows，Linux 有 CI smoke test；
- 10 位种子用户完成观察测试；
- 收集 TTFV、失败步骤和人工救援次数。

退出条件：至少 7/10 位用户完成第一个验证任务，且没有越界文件改动或密钥事故。

### M3：公开 Alpha（建议 2026-09-12 前）

- 公开仓库、许可证、贡献指南和问题模板齐全；
- 课程版本兼容信息上线；
- 脱敏诊断包可导出；
- 至少发布 3 篇配套教程和 1 个完整演示视频。

退出条件：外部用户可以安装、学习、反馈，维护者能够复现失败。

### M4：Cordis Builder Track（建议 2026-10-12 前）

- effect 回滚、reactive dependency、生命周期、HMR、安全边界课程上线；
- 所有理论课程无需 API Key；
- 可观察组件状态与清理结果；
- 故意引入错误后能展示回滚或明确的失败边界。

退出条件：一个会 TypeScript 但没用过 Cordis 的开发者可以写出并验证最小可卸载插件。

### M5：Beta 与生态连接（建议 2026-11-11 前）

- DSH 内置教学插件与 CLI 共用同一课程引擎；
- 核心文档示例全部进入自动验证；
- 建立每周兼容性运行和变化日志；
- 至少 3 位外部贡献者提交课程、适配或修复。

退出条件：项目不再依赖作者逐台手工验证，版本变化能够被自动发现并公开标记。

## 8. 发布门槛

任何公开版本必须同时满足：

- `setup -> check -> reset -> setup` 在支持矩阵全部通过；
- reset 只能作用于带有项目生成标记的明确目录；
- 所有需要 API Key 的课程在运行前显示费用与数据边界；
- 日志和诊断包经过密钥与隐私扫描；
- 每课有版本、系统、时长、权限和改动范围；
- README 使用非官方社区项目表述；
- 已知不兼容课程不会被 CLI 推荐；
- 至少一名没有参与开发的人按发布文档完整走通。

## 9. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| DSH 频繁破坏兼容 | 教程迅速失效 | 版本钉住、兼容矩阵、每周 canary、课程状态标记 |
| 插件安装本身门槛过高 | 新手在学习前流失 | MVP 先用外部 CLI，插件入口后置 |
| 误操作真实项目 | 信任受损 | 生成练习目录、标记文件、路径验证、默认拒绝任意目录 reset |
| API Key 泄漏 | 严重安全事故 | 只读环境变量状态、不回显、不写日志、自动 secrets scan |
| 把“撤销注册”误解成“撤销一切” | 用户高估恢复能力 | 教清系统边界、外部 emission、commit point 和补偿动作 |
| 把依赖声明误解成沙箱 | 恶意插件可逃逸 | 明确 capability access 与 process sandbox 的区别 |
| 课程过度理论化 | 普通用户放弃 | 用户路径只讲行为，形式化内容放 Builder Track 和附录 |
| 内容多但缺乏验证 | 变成普通教程仓库 | 每课必须有机器验收和 reset 才能标记完成 |
| 一开始范围过大 | 无法发布 | 优先完成纵向切片，Cordis 高级课程在公开 Alpha 后开发 |
