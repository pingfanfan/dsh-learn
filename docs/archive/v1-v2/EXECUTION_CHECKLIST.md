# dsh-learn 30 天执行清单（V2，已归档）

> 本清单与 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md) 配套。
> 规则：先完成 P0，再做 P1；每项必须满足验收条件才可勾选。对外创建仓库、发布 npm、发帖和联系他人均需在实际执行前确认账号与文案。

## 优先级与工作量

- `P0`：阻塞第一次公开发布或安全纵向切片；
- `P1`：14 天公开 Alpha 必需；
- `P2`：30 天复利阶段；
- `P3`：有用户证据以后再做。

工作量：`XS` 不超过 2 小时，`S` 半天，`M` 1 天，`L` 2 至 3 天，超过 3 天必须拆分。

## 0. 第一条关键路径

严格按下面顺序推进：

1. `EA-001` 至 `EA-006`：锁定事实和名称；
2. `EA-010` 至 `EA-014`：先把入口内容做出来；
3. `EA-020` 至 `EA-024`、`EA-026` 至 `EA-028`：完成 L01 专用 CLI 纵向切片；
4. `EA-031` 至 `EA-034`：完成 L00/L01；
5. `EA-040` 至 `EA-044`：补 CI 与更新雷达；
6. `EA-050` 至 `EA-055`：找用户、修阻塞、公开 Alpha；
7. `EA-060` 以后：根据真实反馈扩展。

在 `EA-034` 完成前，不做 DSH 内插件，不建立静态网站，不设计通用工作流语言。

## 1. D1：事实、定位与名称

- [ ] **EA-001 `[P0/M]` 锁定第一个 DSH baseline**
  - 产物：`compatibility/baselines.json` 首条记录。
  - 动作：记录 npm 版本、Git commit、Node、pnpm、系统、实测日期和启动命令。
  - 验收：从全新临时目录启动 Web UI；不以 README 或搜索摘要代替本机实测。

- [ ] **EA-002 `[P0/S]` 实测当前官方用户路径**
  - 产物：`research/current-user-path.md`。
  - 动作：运行 Web UI、配置一个 provider、选择练习工作区、完成一项文件任务。
  - 验收：记录每一步、实际耗时、权限提示、写入位置和清理方法。

- [ ] **EA-003 `[P0/S]` 实测官方插件生命周期**
  - 产物：`research/current-plugin-path.md`。
  - 动作：使用独立 profile 完成 add、dump-config、启动、remove。
  - 验收：所有命令来自当前 CLI 或源码；卸载后对应 bundle 不再出现在 profile。

- [ ] **EA-004 `[P0/XS]` 固定产品边界**
  - 产物：README 中的一句话定位和非目标。
  - 验收：明确不做 registry、全量插件扫描、Web 控制台和深度 Cordis 课程。

- [ ] **EA-005 `[P0/XS]` 检查统一名称**
  - 产物：GitHub repo、npm package、社交展示名可用性记录。
  - 验收：主品牌使用 `dsh-learn`；若 npm 裸包名不可用，选择一致的 scope，不临时更换项目名。

- [ ] **EA-006 `[P0/XS]` 建立竞争边界清单**
  - 产物：`research/ecosystem-boundaries.md`。
  - 验收：至少记录官方文档、plugin-registry、dsh-plugin-check、dsh-101、dsh-explain、dsh-plugin-dev；每项只有“链接、作用、我们不重复什么”。

## 2. 24 小时公开入口

- [ ] **EA-010 `[P0/S]` 重写项目首页**
  - 产物：中英文最短 README。
  - 验收：前 1 屏包含对象、结果、当前状态、5 步以内的开始方式、非官方声明和最后实测日期。

- [ ] **EA-011 `[P0/M]` 写当前版本 quickstart**
  - 产物：`docs/quickstart.zh.md`。
  - 验收：全部命令在 baseline 上执行；包含预计时间、系统、网络、API、写入和退出方法。

- [ ] **EA-012 `[P0/S]` 创建兼容状态页**
  - 产物：`docs/status.md` 或 README 状态区。
  - 验收：区分 `verified/community-tested/stale/blocked`；不使用无日期的“支持最新版”。

- [ ] **EA-013 `[P1/S]` 录制真实操作素材**
  - 产物：60 至 90 秒 GIF/视频和 3 张关键截图。
  - 验收：画面来自真实 baseline，没有泄露 API Key、用户名、完整主目录和私人会话。

- [ ] **EA-014 `[P1/S]` 准备首发内容包**
  - 产物：GitHub 发布文案、知乎/公众号长文提纲、X/微博短文、Discussion 草稿。
  - 验收：所有内容回链同一仓库；没有“官方”“最安全”“第一个”等未经证明的表述。

## 3. CLI 纵向切片

- [ ] **EA-020 `[P0/S]` 初始化单包 TypeScript 项目**
  - 产物：`package.json`、锁文件、TypeScript、Vitest、lint/format、CLI bin。
  - 验收：一条命令完成 typecheck、test 和 build；不建立 monorepo。

- [ ] **EA-021 `[P0/S]` 定义统一结果模型**
  - 产物：`PASS/WARN/BLOCKED/FAIL/INTERNAL_ERROR` 类型和退出码。
  - 验收：普通输出说明下一步，`--json` 输出稳定结构，未知异常只在 `--verbose` 展示堆栈。

- [ ] **EA-022 `[P0/M]` 实现 `doctor`**
  - 检查：OS/架构、Node、npx、pnpm、DSH 版本、默认端口、临时目录、API Key 存在性、baseline 状态。
  - 验收：没有 Key 时 L00/L03 仍可继续；每个非 PASS 项都有一条可执行建议；绝不打印 Key 值。

- [ ] **EA-023 `[P0/M]` 实现实例 marker 和安全路径解析**
  - 产物：随机实例 ID、允许根、lab ID、创建版本、初始哈希。
  - 验收：拒绝 `/`、用户主目录、仓库根、空路径、`..`、未展开变量和跳出根目录的符号链接。

- [ ] **EA-024 `[P0/M]` 实现 `start <lab>`**
  - 产物：练习实例、夹具、marker、下一步和可复制提示词。
  - 验收：默认使用系统临时目录；失败时不留下半成品；输出明确绝对路径和预计改动。

- [ ] **EA-025 `[P1/M]` 抽取 verifier runner**
  - 前置：L01 已被外部用户走通，且第 2 条实验准备开发。
  - 产物：从 L01 专用检查中抽出的受控子进程、超时、输出上限和结构化断言。
  - 验收：区分“用户没做”“结果不对”“验证器失败”“超时”；不把用户输入拼进 shell。

- [ ] **EA-026 `[P0/S]` 实现 `check`**
  - 产物：每项检查、实际值、期望值、修复建议和退出码。
  - 验收：只有确定性证据全部通过才返回 PASS；模型回复文字不作为证据。

- [ ] **EA-027 `[P0/M]` 实现 `reset --dry-run`**
  - 产物：动作清单、恢复修改、删除生成文件、重复运行保护。
  - 验收：dry-run 与正式动作同源；marker 损坏或路径异常时默认拒绝；reset 后初始哈希恢复。

- [ ] **EA-028 `[P0/M]` 建立破坏性路径测试**
  - 产物：至少 20 个路径、符号链接、marker 和权限异常测试。
  - 验收：全部安全失败，没有测试能让 reset 触及允许根以外的文件。

- [ ] **EA-029 `[P1/M]` 实现脱敏 `report`**
  - 产物：版本、系统、lab、步骤、检查结果和脱敏错误。
  - 验收：默认排除 Key、Authorization、完整主目录、会话正文、文件正文和环境变量全集；导出后再次 secrets scan。

## 4. 首批实验

- [ ] **EA-030 `[P2/S]` 定义最小 `lab.json`**
  - 前置：L01 已通过外部测试，且至少有第 2 条实验需要复用配置。
  - 产物：schema v0、解析器和 1 个有效示例。
  - 验收：只包含首批实验需要的字段；不提前加入分支、循环、远程动作等工作流功能。

- [ ] **EA-031 `[P0/S]` 完成 L00-environment**
  - 产物：无模型、无 Key 环境实验。
  - 验收：能确认用户可运行的下一条路径；失败信息与 `doctor` 一致。

- [ ] **EA-032 `[P0/M]` 设计 L01-first-result 夹具**
  - 产物：一个小型、可测试、不含真实项目内容的练习项目。
  - 验收：任务只允许写入 1 至 2 个明确文件；成功可以由测试和文件断言决定；预计 15 分钟内完成。

- [ ] **EA-033 `[P0/M]` 完成 L01 E2E**
  - 流程：`doctor -> start -> DSH 操作 -> check -> reset -> start`。
  - 验收：在 baseline 上连续执行 2 次结果一致；reset 后无清单外改动。

- [ ] **EA-034 `[P0/M]` 让外部用户走通 L01**
  - 产物：首轮 3 位用户的耗时、阻塞和救援记录。
  - 验收：至少 2/3 位不经实时操作代劳完成；未完成者的第一个阻塞点已记录。

- [ ] **EA-035 `[P2/M]` 完成 L02-fix-and-reset**
  - 验收：用户经历一次失败、修正后通过，reset 后全部初始哈希恢复。

- [ ] **EA-036 `[P2/M]` 完成 L03-plugin-lifecycle**
  - 验收：使用本地、无安装脚本的示例 bundle；只调用官方 `dsh plugin`；安装和卸载状态都能验证。

## 5. CI、版本与更新雷达

- [ ] **EA-040 `[P0/S]` 建立基础 CI**
  - 验收：install、typecheck、test、build 在 PR 和 main push 运行。

- [ ] **EA-041 `[P0/M]` 建立系统矩阵**
  - 验收：macOS、Ubuntu、Windows 运行 CLI 与路径安全测试；不能实测的 DSH 路径标成 community-tested 或 blocked。

- [ ] **EA-042 `[P1/M]` 实现每日上游 canary**
  - 动作：发现官方 npm/commit 变化，运行 L00 和无 Key smoke test。
  - 验收：变化或失败会产生可见报告；不会静默把 current baseline 改成通过。

- [ ] **EA-043 `[P1/S]` 生成兼容状态**
  - 产物：`baselines.json`、历史记录和 README badge 数据。
  - 验收：每条状态包含证据日期、系统和运行编号；master canary 与已发布版本分开。

- [ ] **EA-044 `[P1/M]` 检查文档命令漂移**
  - 验收：核心文档中的可执行命令至少 90% 自动 smoke；不可自动执行的命令有明确原因。

- [ ] **EA-045 `[P2/S]` 生成每周变化草稿**
  - 产物：版本、命令、文档、失败状态的结构化差异。
  - 验收：脚本只生成事实材料，最终摘要需人工确认，不自动发布。

## 6. 公开 Alpha 与种子用户

- [ ] **EA-050 `[P0/S]` 确定 Alpha 支持矩阵**
  - 验收：每个系统标记正式支持、CI 检查、community-tested 或不支持；Windows 原生与 WSL 分开。

- [ ] **EA-051 `[P0/S]` 建立反馈模板**
  - 产物：Bug、教程问题、版本失效、配方建议 4 种 issue form。
  - 验收：默认要求版本、系统、lab、步骤和脱敏输出，不要求上传私人会话。

- [ ] **EA-052 `[P1/M]` 完成 5 位用户私有 Alpha**
  - 验收：记录 TTFV、完成率、第一个阻塞、救援次数；不只收主观好评。

- [ ] **EA-053 `[P1/M]` 修复前 3 个共同阻塞**
  - 验收：每个修复都有回归测试或明确文档检查；再次找至少 2 位用户复测。

- [ ] **EA-054 `[P1/S]` 发布或准备 npm 0.1.0**
  - 验收：从空目录使用公开命令运行；包内无凭据、临时路径和私有素材；版本与 README 一致。

- [ ] **EA-055 `[P1/S]` 发布带数据的 Show and Tell**
  - 验收：包含支持基线、完成率、TTFV、已知限制和复现命令；不只写项目愿景。

- [ ] **EA-061 `[P1/S]` 完成 60 至 90 秒演示**

## 8. 第三方配方和合作

- [ ] **EA-070 `[P1/S]` 定义事实型测试标签**
  - 标签：`discovered/install-passed/boot-passed/task-passed/community-tested/stale`。
  - 验收：README 明确它们不代表安全审计或官方背书。

- [ ] **EA-071 `[P1/M]` 完成第一条第三方任务配方**
  - 验收：从用户目标开始，固定来源版本，包含安装、验证、卸载、权限和构建脚本提示；作者有机会核对。

- [ ] **EA-072 `[P1/S]` 联系 3 位插件作者**
  - 验收：提出具体合作内容，不群发模板；目标是共同维护验证步骤或修正事实。

## 11. D14 发布门槛

以下条件必须同时满足：

- [ ] `doctor -> start L01 -> check -> reset -> start` 在正式支持环境通过；
- [ ] reset 危险路径测试全部通过；
- [ ] 日志和诊断没有高危凭据命中；
- [ ] README、quickstart 和 CLI 使用同一 baseline；
- [ ] 已知失效路径显示 stale/blocked；
- [ ] 至少 7/10 位种子用户完成核心实验，或已经明确执行 Pivot；
- [ ] 至少 1 名没有参与开发的人按公开文档从空目录完整走通；
- [ ] README 明确非官方社区项目；
- [ ] 对外内容使用真实截图和实测数据，没有夸大安全、兼容或官方关系。
