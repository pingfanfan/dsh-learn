# dsh-learn 产品与课程规格（V1，已归档）

> V1 长期产品规格：当前 MVP 已收缩为“轻量 CLI + 2 条可验证实验 + 更新雷达”。近期范围与取舍以 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md) 为准，本文用于 30 天以后评估扩展课程时参考。

## 1. 产品定义

`dsh-learn` 由三部分组成：

1. **课程仓库**：保存课程说明、提示词、练习夹具、预期产物和版本信息；
2. **本地 CLI**：负责环境检查、创建练习工作区、显示下一步、验证结果、重置和导出脱敏报告；
3. **可选 DSH 教学插件**：在第二阶段提供会话内课程导航和进度显示，但不复制验证逻辑。

MVP 必须先证明课程闭环，不能把时间花在漂亮的 Web 控制台上。CLI 和插件调用同一个课程引擎，课程内容也只能有一个事实源。

## 2. 核心使用流程

建议的最终命令体验：

```sh
npx dsh-learn preflight
npx dsh-learn start U01
npx dsh-learn next
npx dsh-learn check U01
npx dsh-learn reset U01
npx dsh-learn report --sanitize
```

首版如果尚未发布 npm 包，可以使用仓库内命令，但 README 的操作数量不超过 5 步。

### 2.1 `preflight`

检查：

- 操作系统与架构；
- Node.js 是否满足当前上游要求；
- npm/npx 是否可用；
- DSH 是否能启动或解析版本；
- 默认端口是否可用；
- 练习目录是否可写；
- API Key 只检查“存在/不存在”，绝不显示值；
- 当前课程是否与检测到的 DSH 基线兼容。

输出必须分成 `PASS`、`WARN`、`BLOCKED`，每个非 PASS 项都给一条下一步。没有 API Key 不能阻止无 Key 课程。

### 2.2 `start <lesson>`

- 校验课程前置条件；
- 创建新的练习实例目录；
- 写入不可伪造为普通项目的实例标记；
- 复制固定夹具并计算初始清单；
- 显示本课时间、权限、费用、文件边界和启动命令；
- 将状态设为 `ready`，不能未经用户操作直接判定完成。

### 2.3 `next`

- 显示当前课程的下一项操作；
- 不替用户自动批准 DSH 权限；
- 能够复制提示词，但不把 API Key 写进提示词；
- 用户尚未完成前置步骤时，说明缺少的证据。

### 2.4 `check <lesson>`

- 校验课程产物，而不只检查某个文件是否存在；
- 区分“课程未做”“做了但结果不对”“验证器自身失败”；
- 输出检查项、实际值、预期值和修复建议；
- 通过后生成一份本地 completion record；
- 验证过程默认不发网络请求。

### 2.5 `reset <lesson>`

- 只接受含有效 dsh-learn 实例标记的目录；
- 展示将被恢复或删除的明确路径；
- 支持 `--dry-run`；
- 重复运行得到相同结果；
- 不接收工作区根目录、用户主目录、`/`、`~` 或未解析变量作为目标；
- reset 后重新执行 `start` 应得到相同基线。

### 2.6 `report --sanitize`

默认包含：

- dsh-learn 版本；
- 课程 ID 与步骤；
- DSH 版本或 commit；
- Node.js、系统和架构；
- 通过/失败检查；
- 经过路径归一化的错误；
- 用户主动选择附加的日志片段。

默认排除：

- API Key、Authorization Header 和凭据文件；
- 用户名及完整主目录；
- 练习区外的文件名和正文；
- 完整会话内容；
- Git 凭据、远程 URL 中的 token；
- 环境变量全集。

## 3. 课程设计原则

每课都遵循同一个闭环：

`说明边界 -> 建立练习现场 -> 用户操作 -> 收集本地证据 -> 自动验收 -> 解释结果 -> 安全重置`

课程不能只包含“复制这段命令”。它必须回答：

- 这一步为什么存在；
- DSH 会得到什么权限；
- 会改动哪些位置；
- 什么结果算成功；
- 出错以后先看哪里；
- 哪些影响能自动撤销，哪些已经越过系统边界。

## 4. 普通用户路径（User Track）

### U00：模型、Agent 和 Harness 是什么

- 对象：Persona A；
- 时间：5分钟；
- API Key：不需要；
- 文件写入：只写课程状态；
- 目标：能够区分 DeepSeek 模型、API、DSH 进程、工作区和插件；
- 实验：给出 5 个行为，让用户判断由模型、Harness 还是外部工具完成；
- 验收：至少答对 4 个，并知道 Harness 可能读取文件、执行命令和请求权限；
- 重置：删除本课状态。

### U01：环境体检与启动

- 时间：10至15分钟；
- API Key：启动可不需要，模型任务需要；
- 权限：只创建练习目录和启动本地服务；
- 目标：完成 preflight，运行官方 Web UI，识别地址和工作区状态；
- 练习：创建 `hello-dsh` 练习项目，选择为工作区；
- 验收：服务可达、练习目录可写、工作区已准备；
- 常见失败：Node 版本、端口占用、npx 下载、路径空格、防火墙；
- 重置：停止课程启动的进程并删除生成目录，不能停止非课程进程。

### U02：第一个只读任务

- 时间：10分钟；
- API Key：需要，并提示可能产生调用费用；
- 权限：仅允许读取练习工作区；
- 目标：让 DSH 概括一个小项目，并引用正确文件；
- 练习提示词：要求找出项目入口、两项功能和一个故意埋入的事实；
- 验收：答案包含 manifest 中的三个事实及相应文件位置；
- 教学点：模型回答不等于验证，课程检查器从夹具事实单独判断；
- 重置：清理会话导出和课程状态，夹具保持初始状态。

### U03：计划、工具和权限提示

- 时间：10至15分钟；
- API Key：需要；
- 权限：读文件、运行一条无副作用检查命令；
- 目标：看懂计划、工具调用、命令参数和批准提示；
- 练习：让 DSH 先提出计划，再运行指定的只读测试；
- 验收：用户识别将执行的命令、工作目录和预期输出；
- 故意失败：提供一条越出练习目录的请求，让用户拒绝；
- 重置：没有工作区改动，只清理状态。

### U04：第一次安全修改

- 时间：15分钟；
- API Key：需要；
- 权限：只修改 manifest 列出的 2 个练习文件；
- 目标：让 DSH 完成一个小功能并查看 diff；
- 练习：修改一个纯文本/小型代码项目中的明确行为；
- 验收：行为测试通过、允许文件 diff 符合约束、没有额外文件改动；
- 教学点：不要只看最终回复，要看实际 diff 和测试；
- 重置：根据初始快照恢复练习文件。

### U05：测试失败与恢复

- 时间：15至20分钟；
- API Key：需要；
- 权限：修改练习文件、运行限定测试命令；
- 目标：经历一次失败，定位错误，重新运行验证，并恢复基线；
- 练习：夹具包含一个诱发错误的边界条件；
- 验收：第一次检查明确失败，修正后通过，reset 后所有初始哈希恢复；
- 教学点：Agent 的“已完成”不是验收条件；
- 重置：必须通过路径标记、哈希和幂等测试。

### U06：会话记录与脱敏反馈

- 时间：10分钟；
- API Key：不额外需要；
- 权限：读取课程自己的日志与状态；
- 目标：导出一份可以公开报告的最小诊断包；
- 练习：在夹具日志中放置伪造 token、用户名和主目录，验证清洗；
- 验收：诊断信息足够定位课程失败，敏感样例全部被替换；
- 教学点：报告错误不等于公开完整会话；
- 重置：删除诊断包。

### U07：插件是什么（可选桥接课）

- 时间：10分钟；
- API Key：不需要；
- 权限：无第三方代码执行；
- 目标：看懂插件可以增加工具、UI、模型适配和工作流，以及安装第三方代码的风险；
- 实验：阅读两个经过裁剪的插件 manifest，判断权限和依赖；
- 验收：用户能指出插件来源、版本、依赖和可访问能力；
- 重置：清理状态。

完成 U00-U06，视为普通用户核心路径完成。U07 是进入 Builder Track 的桥，不应拖慢首次价值。

## 5. 插件开发路径（Builder Track）

### B00：用两个问题理解 Cordis

- 时间：10分钟；
- API Key：不需要；
- 目标：理解“卸载后是否恢复现场”和“依赖变化时谁该启停”；
- 实验：观察一个普通事件监听器留下残留，再观察 Cordis 管理的监听器被撤销；
- 验收：用户能用自己的话区分时间可组合性和空间可组合性；
- 理论范围：不引入形式化符号和证明。

### B01：最小组件和 Context

- 时间：20分钟；
- 目标：运行一个只打印生命周期事件的最小插件；
- 教学点：component、fiber、context、`apply`；
- 验收：加载一次、卸载一次，日志中没有重复实例；
- 反例：把状态挂在全局变量，观察其逃出组件生命周期。

### B02：Revertible Effect 实验

- 时间：30分钟；
- 目标：注册工具、监听器和计时器，并把创建与 inverse 放在同一处；
- 教学点：`ctx.effect`、LIFO 恢复、dispose 至多执行一次；
- 验收：卸载前资源存在，卸载后注册项为 0，二次 dispose 不破坏状态；
- 故意错误：漏掉 inverse，使测试暴露残留；
- 论文对应：3.1、5.1.1。

### B03：Reactive Coeffect 实验

- 时间：30分钟；
- 目标：建立 provider 和 consumer，consumer 明确声明依赖；
- 教学点：provide/inject、ACTIVE/INACTIVE、依赖变化通知；
- 验收：无 provider 时 consumer 不激活；provider 出现后激活；provider 撤走时 consumer 先卸载；新 provider 出现后重新激活；
- 故意错误：循环依赖，观察组件保持不活跃并输出诊断；
- 论文对应：3.2、5.1.2、5.1.3。

### B04：声明式配置与增量协调

- 时间：25分钟；
- 目标：用配置 entry 控制组件实例、配置和 disabled 状态；
- 教学点：配置树是事实源，loader 做 reconciliation；
- 验收：改一个 entry 只影响对应 fiber，不全量重启无关组件；
- 故意错误：非法配置被阻止并保留旧状态；
- 论文对应：5.2.1。

### B05：HMR 与失败回滚

- 时间：30分钟；
- 目标：修改组件源码后热替换，并在语法错误时回到旧版本；
- 教学点：旧 fiber dispose、新 fiber install、缓存备份、事务式 reload；
- 验收：正常修改不重启进程；故意语法错误不会留下半重载状态；修复后重新加载；
- 论文对应：5.2.2。

### B06：Isolation、Interception 与能力访问

- 时间：30分钟；
- 目标：让同一个依赖 key 在两个子 context 解析为不同 provider，并添加只读拦截策略；
- 教学点：isolation 改变“解析到什么”，interception 改变“怎样使用”；
- 验收：两个环境互不污染；未声明依赖的访问被拒绝；只读策略阻止写操作；
- 边界：明确这只能约束经代理访问的能力，不能隔离有宿主运行时权限的恶意代码；
- 论文对应：3.2.3、5.1.4、6.3。

### B07：系统边界、提交点与补偿

- 时间：25分钟；
- 目标：区分可恢复的本地 scratch 状态和已经发往外部的请求；
- 实验：本地临时文件可 reset，模拟“已发送消息”只能延迟提交或执行补偿动作；
- 验收：课程不能把外部 emission 标记为已完整回滚；
- 论文对应：6.1。

### B08：依赖版本与发布检查

- 时间：25分钟；
- 目标：为插件声明 peer dependency、兼容基线和 smoke test；
- 教学点：接口漂移、key 冲突、版本范围、命名空间和结构兼容局限；
- 验收：不兼容版本在安装/课程检查阶段被拦截；发布包包含版本、测试和清理证据；
- 论文对应：6.6。

## 6. 课程契约

每课使用机器可读 manifest。字段名称可以在原型后调整，但含义不能缺失。

```yaml
id: U04
title: 第一次安全修改
track: user
level: beginner
duration_minutes: 15
requires:
  api_key: true
  lessons: [U01, U02, U03]
  dsh: "PINNED_AFTER_DSHL_001"
  node: "^22.19.0 || >=24"
supported_platforms: [darwin-arm64, darwin-x64, win32-x64, linux-x64]
permissions:
  filesystem:
    read: ["${LESSON_ROOT}/**"]
    write:
      - "${LESSON_ROOT}/src/example.ts"
      - "${LESSON_ROOT}/tests/example.test.ts"
  commands:
    - "npm test -- --runInBand"
external_effects:
  network: model-api-only
  estimated_cost: variable
artifacts:
  - "src/example.ts"
  - "tests/example.test.ts"
verifier: "./verify.mjs"
reset: "./reset.mjs"
compatibility:
  last_tested_at: "2026-08-13"
  dsh_commit: "TO_BE_PINNED"
```

### 6.1 manifest 验证规则

- `id` 全局唯一且不复用；
- 依赖图不能有环；
- `write` 路径必须位于 `${LESSON_ROOT}`；
- 需要网络/API 的课程必须声明；
- verifier 和 reset 必须存在并进入自动测试；
- 兼容范围不能只写 `latest` 或 `*`；
- 文件列表与实际 diff 不一致时课程失败；
- 课程不兼容时状态为 `blocked`，不能静默继续。

## 7. 课程状态模型

```text
not_started -> ready -> in_progress -> passed
                  |          |
                  |          +-> needs_help
                  +------------> blocked

任何状态 -> stale（上游兼容性失效）
任何已创建实例 -> reset -> ready/not_started
```

- `blocked`：前置条件不满足，用户尚未开始任务；
- `needs_help`：用户执行过，但结果未通过；
- `stale`：当前 DSH 基线未验证或明确不兼容；
- `passed`：本地 verifier 通过，不能由模型自己声明；
- 状态变化写入实例内的 append-only event log，再投影成当前状态，便于诊断但不保存会话正文。

## 9. 技术架构约束

### 9.1 共享核心

- CLI 与 DSH 插件不各自实现进度、验证和 reset；
- 课程 manifest、状态机、路径策略和脱敏规则放在无 UI 的 core；
- 输出层只接收结构化结果，便于终端、Web UI 和测试复用；
- 课程验证器默认作为受控子进程运行，超时后终止。

### 9.2 可恢复性

- 课程 setup 产生的每个资源都必须登记对应清理动作；
- 清理以逆序执行，并且每项最多生效一次；
- 中途失败时只执行已经登记的清理动作；
- reset 不假设课程完整执行，必须支持部分完成状态；
- 写入基线前创建明确快照，验证恢复后的哈希；
- 外部网络 emission 不纳入“完整恢复”承诺。

### 9.3 依赖与生命周期

- 课程前置条件使用声明式依赖，不在每课里手写不同的检测循环；
- 依赖缺失时课程保持 blocked，不进入半初始化；
- 依赖提供者变化时重新评估课程兼容性；
- 插件组件使用 Cordis effect/context API 管理注册和资源；
- 避免全局监听器、全局可变状态和逃出 fiber 生命周期的闭包。

### 9.4 配置与 HMR

- 配置文件是课程组合的事实源；
- HMR 只用于开发者体验，不作为正确性前提；
- reload 失败必须保留上一个可用课程版本；
- 课程内容变化导致 verifier 契约变化时，旧实例标记为 stale，不自动套用新验证器。

## 10. 安全和隐私

### 10.1 文件边界

- 默认练习根目录使用系统临时目录或用户显式指定的空目录；
- 每个实例包含随机 ID、创建版本和 marker；
- 删除前验证 marker、真实路径、父目录和允许根；
- 符号链接不能把写入或 reset 引向练习目录外；
- 自定义课程必须先通过静态路径检查。

### 10.2 命令边界

- 每课声明允许的命令模板和工作目录；
- verifier 不拼接未经验证的用户输入进入 shell；
- 运行命令设置超时、输出上限和退出码检查；
- 初学者课程不要求管理员/root 权限；
- 任何安装脚本不得静默修改全局 Git、shell profile 或系统配置。

### 10.3 凭据

- 只检查凭据是否存在，不读取后持久化；
- 输出、快照、诊断包和测试夹具都进行秘密扫描；
- 文档使用占位符，不给出看似真实的 Key；
- 发现疑似真实凭据时停止生成报告并提示用户轮换。

### 10.4 访问控制与沙箱

课程必须使用一致表述：Cordis 的 inject/intercept 可以限制组件通过代理能访问的能力，但如果不受信任代码已经拥有宿主 Node.js 运行时权限，它仍可能绕过语言层代理。运行不受信任代码需要独立进程、受限运行时、容器或其他外部沙箱。

## 11. 兼容性策略

- 开发时锁定一个已实测的 DSH commit/npm 版本；
- `compatibility/baselines.json` 保存支持、实验性、失败和未知状态；
- 每周对最新上游执行无 Key canary；
- canary 失败只把最新版本标记为未知/失败，不破坏稳定基线；
- 每课显示“最后实测”，超过约定期限后显示提醒；
- 修复破坏变化时增加迁移说明和前后行为测试；
- 发布课程时同时固定夹具版本和 verifier 版本。

## 12. 可观测性与数据

本地默认记录：课程 ID、状态变化、步骤耗时、检查结果和错误分类。默认不上传。

如以后增加匿名统计，必须：

- 明确 opt-in；
- 上传前展示字段；
- 不上传提示词、回答、路径、文件内容和凭据；
- 用户可随时关闭并删除本地统计；
- 没有遥测也能完成所有课程。

## 13. 内容标准

每课文档固定包含：

1. 你会得到什么；
2. 预计时间；
3. 前置条件；
4. 是否用 API 和可能产生费用；
5. DSH 会获得什么权限；
6. 只会改动哪些文件；
7. 操作步骤；
8. 成功时应看到什么；
9. `check` 怎样判断；
10. 常见失败；
11. reset 的范围；
12. 最后实测版本和日期。

截图只能辅助，不能成为唯一验收依据。命令和预期输出必须进入自动文档测试。

## 14. 单课完成定义（Definition of Done）

一课只有满足全部条件才可标记完成：

- manifest 通过 schema 和依赖图验证；
- setup 在干净目录可重复执行；
- 至少一个成功测试、一个预期失败测试；
- verifier 能区分未做、做错和内部错误；
- reset 支持 dry-run、部分状态和重复运行；
- reset 后基线哈希一致；
- 文件和命令不越出声明边界；
- 文档包含费用、权限、改动和版本；
- 支持矩阵通过；
- 一位目标用户不经作者口头补充完成；
- 诊断报告不泄漏夹具中的伪造敏感信息。

## 15. MVP 发布包

首个公开 Alpha 应包含：

- U00-U06；
- preflight/start/next/check/reset/report；
- macOS、Windows、Linux 兼容状态；
- 一个极小代码夹具和一个纯文本夹具；
- 版本基线、变化日志和已知问题；
- 3 篇文章：认识 DSH、第一次安全任务、失败与恢复；
- 1 个完整录屏，从空目录开始，包含一次故意失败；
- GitHub Issue 模板：安装失败、课程失败、内容问题、上游最小复现；
- 安全说明、许可证和非官方声明。

Builder Track 和 DSH 教学插件不应阻挡 Alpha 发布。
