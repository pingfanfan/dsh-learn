# dsh-101 v0.1.7：新手安装路径和 `web` profile 安全门禁更新

截至 2026 年 8 月 14 日，bill9109/dsh-101 的 main 已从 `086de430` 前进 3 个 commit，到达 `f3e801e`；当前 README 和 package manifest 标注的发布版本是 `@bill9109/dsh-101@0.1.7`。

这不是 DeepSeek Harness 官方发布，而是 DSH 生态项目的一次更新。它对新手最有价值的变化，不是多了多少阅读器功能，而是把安装边界写得更清楚了。

## 这次更新了什么

- README 改成双语、版本化的安装说明，并增加升级、卸载、排错和安全入口。
- 提供一键安装脚本，把 `profile/` 放进独立的 `dsh-101` profile，再安装 bundle。
- `install.sh` 现在会直接拒绝 `--profile web`。
- 默认端口是 `3081`，用于和官方 Web GUI 的 `3080` 并行运行。
- GitHub 安装直接使用仓库中已提交的 `lib/` 构建产物，通常不需要用户先构建源码。
- profile 的 bundles 组合明确包含 `dsh-base`、`dsh-web-app` 和 `@bill9109/dsh-101`。

## 完全新手应该怎么理解

把 dsh-101 想成一套独立的阅读器 profile，不要把它当成官方 DSH Web UI 的一个小主题。它自己的 bundle 会关闭 `ui-layout`；如果混进 `web` profile，可能让默认 Web UI 的 sidebar、conversation 和 app-shell 一起等待 layout 服务。

因此第一次尝试时，不要修改日常 `web` profile。先使用独立名称和独立端口：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/bill9109/dsh-101/main/scripts/install.sh) github:bill9109/dsh-101#v0.1.7
dsh --profile dsh-101 --port 3081
```

安装后可以检查 profile 的组合记录：

```bash
python3 -c "import json; print(json.load(open('$HOME/.dsh/profiles/dsh-101/package.json'))['dsh']['profile']['bundles'])"
```

预期至少能看到：

```text
@deepseek-ai/dsh-base
@deepseek-ai/dsh-web-app
@bill9109/dsh-101
```

如果只是想换端口，优先在启动时使用 `--port`，不要为了一个端口去改官方 `web` profile。卸载 bundle 时，使用它提供的 profile 命令；是否删除整个 profile 目录，要单独确认，不要把删除动作混在第一次安装实验里。

## 这次复核没有证明什么

- dsh-101 不是 DeepSeek 官方插件，也没有因此获得官方兼容或安全背书。
- dsh-learn 本轮只做了公开仓库静态复核，没有下载、安装或启动 dsh-101。
- 没有动态验证 macOS、Windows 或 Linux 的实际页面行为。
- 没有调用模型 API，也没有使用或保存任何 API Key。

所以这张卡能证明的是：当前生态项目 README、manifest、profile 和安装脚本怎样描述安装边界；它不能替代你自己机器上的版本、路径、profile、日志和端口回执。
